Run your own copy

Italiano · ClanBoard

What you need

  • A machine that runs containers, with Docker and the compose plugin. The database comes up as a container too, so nothing else has to be installed.
  • A key for the Clash of Clans developer API. A key is tied to the public address of the machine that uses it: make it for the machine that will host the copy, or the game answers that the authorization is not valid.
  • A Telegram bot from BotFather, with its token. One bot serves one clan.

Three commands

Clone the repository, then, inside it:

docker compose up -d db
docker compose run --rm bot setup
docker compose up -d

The first command raises the database, the second asks what your copy needs to know, the third starts the bot. From there the bot is alive and answers in the groups where you put it.

What setup asks

setup asks four things and stores them encrypted in the database:

  • The Telegram token given by BotFather.
  • One or more keys of the Clash of Clans API.
  • The public address of the source code of your copy, which the licence requires.
  • The Telegram id that receives the alerts of the copy.

The last two accept an empty answer and can be set later with secret source_url and secret owner_id: the address of the source usually exists only after you have published your copy. There is no configuration file, not now and not ever, and nothing of this is written in clear text.

Managing the copy

Every command runs from the terminal of the machine:

docker compose run --rm bot secret <kind>
docker compose run --rm bot addbot
docker compose run --rm bot addclan
docker compose run --rm bot status
docker compose run --rm bot retention --dry-run

secret writes or replaces one of the facts above, addbot adds another bot, addclan ties a clan to a group, status says how the copy is doing, and retention with --dry-run counts what the cleanup would delete without deleting it.

Two more kinds are worth knowing by name. secret channel_url holds the address of the official community of the copy: when it is set, the home page and /support show the link, and when it is not, nothing of it appears anywhere. secret otp_reset, given the username or the Telegram id of a manager, clears the Authenticator code of that person from the server: it is the only way back in when the phone with the codes is gone, and it runs on the machine, never from a chat.

The Mini App

Inside Telegram everyone opens their own Mini App from the button on the message pinned in the clan group. The button shows up by itself once your copy has two things: the public address of the service, stored with secret site_base, and the Mini App registered on the console bot of the copy.

The Mini App is registered once, from BotFather: /newapp, then the console bot, short name app and address <site_base>/app. Without a public address the pinned message stays as it is, with no button, and the rest of the copy works the same.

Whoever opens the page is recognised by the signature Telegram hands over at the opening: what they can do is decided by the bot from the role the game gives their village, not by the page.

Backup and watchman

ops/vps/backup.sh takes the dump of the database, copies the master key out of its volume and then keeps only the three most recent dumps in the backup folder, deleting the older ones. It cleans up only after a dump that worked, and never touches the master key. ops/vps/guard.sh watches the containers, the age of the last dump, the size of the database and the errors in the log, and writes to the owner when something is off.

Both are meant to run on a schedule of the machine that hosts your copy. That schedule stays outside the repository, because it belongs to your machine and not to the program.

Ops: how your copy is doing

The health of a copy is visible inside Telegram only, in the console bot, and only to the id set with secret owner_id: the panel has an Ops section with the memory and the processor of each container, the load and the free memory of the machine, the size of the database, the age of the last dump, how long the last round of checks took, the commands from the app still waiting, the recent errors, the answer of the public probe and the Clash keys still alive. Green means the number is inside the ceilings decided for the copy, yellow that the measure is missing, red that it is over.

None of this needs a scheduler of the machine or the socket of Docker. Every container measures itself from its own cgroup files, the bot asks the database its size in SQL, reads the age of the dump from the backup log mounted read only, and calls status.json on the public address of your copy from the outside, which is the proof that the tunnel and the web answer. When something goes over a ceiling the owner gets one message, once, until the number comes back down.

There is no ops page on your domain: the web serves the anonymous status page and nothing else with numbers in it.

What the licence asks of you

ClanBoard is published under the AGPL-3.0. Running a modified copy that people can reach over a network means publishing your source and setting its address with secret source_url: the bot shows it to whoever asks, in /support.

An unmodified copy has nothing to publish, but the address of this source is still the honest answer to give.
